## 1. 为什么这一步决定 skill 的可信度

观察对象做得好的原因通常是两件事的乘积：

```
好结果 = 方法正确 × 资源到位
```

用户只看得见前者，你却能同时看见两者。**如果把后者也提炼成方法，产出的 skill 表面完整、实际无法执行。**

用户的真实体验会是：照着 skill 做了，但因为拿不到同样的数据、没有人手、没有实验平台，结果做不出来 → 判定"skill 没用"。

**因此：分离资源条件不是学术洁癖，是可用性工程。**

## 2. 分离表

| 属于**方法**（可迁移） | 属于**条件**（不可迁移） |
|---|---|
| 选择某种识别策略的判断依据 | 他能拿到某个专有数据库 |
| 度量构造与验证的流程 | 他有实验室、实验平台或被试池 |
| 论证结构与叙事顺序 | 他有博士生团队与合著网络 |
| 决策标准与取舍规则 | 他的机构位置与话语权 |
| 对失败模式的预判 | 他的时代背景与政策环境 |
| 对边界的界定方式 | 他积累的学术声誉 |
| 质量门禁与自检流程 | 他所在的团队工作节奏 |

**判别方法**：这句话如果对"资源不足的人"也成立，它就是方法；如果只对资源充足的人成立，它就是条件。

## 3. 五问检验

对每条提炼出的方法，依次问：

1. **资源问**：如果用户**没有**相关数据/平台/团队，这条还成立吗？
   - 不成立 → 移出正文，进"不该照抄"，并给替代路径

2. **时代问**：这条依赖某个特定时期的政策/技术/市场结构吗？
   - 依赖 → 标注适用时间窗，给出推广方式

3. **规模问**：这条在小样本/小市场上还成立吗？
   - 不成立 → 标注最小样本要求

4. **失败问**：他自己做错过吗？有没有反例？
   - 有反例且 skill 没提 → 严重问题，说明提炼不完整
   - 没有任何失败案例的 skill 几乎肯定是选择性叙述

5. **读者问**：一个能力等于该作者的用户，照着做能出结果吗？
   - 不能 → skill 的定位错了，应该明说"这是资源门槛型工作"

## 4. 条件缺失时的替代路径

**不要只说"照抄不了"**，要给替代。常见替换：

| 原条件 | 替代路径 |
|---|---|
| 专有数据库 | 公开数据的同类代理；或换问题使其不依赖该数据 |
| 实验/被试 | 观察数据 + 工具变量；或错位事件研究 |
| 完整团队 | 缩小问题范围；用公开代码/数据流水线替代人力 |
| 特定政策窗口 | 同类制度的其他时点/其他地区（多断点交认） |
| 长期跟踪数据 | 短窗口高频数据 + 更严格的识别 |
| 行业内部数据 | 公开同类指标 + 测量验证 |

**写替代路径时同样要过五问检验**——替代方案本身也可能不成立。

## 5. "不该照抄"章节怎么写

这是本 skill 产出物**最有价值的部分**。只有用户相信你指出了边界，才会相信正文。

### 结构

```markdown
## 不该照抄的地方

诚实说明本框架的局限：

- **样本选择偏差**：<他拥有的条件是什么，你不能假设用户也有>
- **路径不唯一**：<读者容易误以为"必须用 X"，实际核心是 Y>
- **规模不可比**：<产出节奏与人手配置的差异>
- **归纳非定理**：<这个框架是从什么样本反推的，适用边界在哪>
- **别把综述当原创**：<某一类成果被误模仿的风险>
```

### 写作要求

- **每条都要给出用户的下一步动作**，不能只是泼冷水
- **不要写成免责声明堆砌**。3–6 条，每条有用，胜过 10 条空话
- **要敢写**。一个没有边界说明的方法 skill，是在消耗用户信任换显得权威

## 6. 过度提炼的另一种失败

除了"把条件当方法"，还有反向失败：**把方法稀释成条件**。

| 过度提炼 | 症状 | 正确做法 |
|---|---|---|
| 抽象到无法执行 | "要重视数据"、"要有创新意识" | 保留具体动作与判据 |
| 抹平差异 | 把所有作品说成同一个套路 | 保留边界与例外 |
| 假装普适 | "任何学科都适用" | 限定适用领域 |
| 只留成功案例 | 全是正面经验 | 保留失败与反例 |

**检验**：把提炼结果交给一个陌生人，他能否**照着做出第一个动作**？不能 → 过度抽象了。
